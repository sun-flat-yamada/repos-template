# Security & Defense Guide - {PROJECT_NAME}

## 1. Zero-Leak Secret Defense Philosophy

We operate on a **Zero-Leak Policy**: under no circumstances should private keys, credentials, API secrets, or PII enter repository history.

### What is Protected?
- API Keys (AWS, OpenAI, Anthropic, Google Cloud, GitHub tokens)
- Cryptographic private keys (`.pem`, `.key`, `id_rsa`)
- Certificate authorities and keystores (`.crt`, `.keystore`)
- Environment configurations (`.env*`)

### How Secrets are Guarded
1. **Pre-Commit Hook**: Blocks commits containing sensitive file types or common token patterns (`.githooks/pre-commit`).
2. **Gitleaks CI Job**: Scans entire git history on every push and PR (`.github/workflows/secret-scan.yml`).
3. **Repository Exclusion**: Comprehensive exclusion in `.gitignore`.

## 2. Indirect Prompt Injection & "Clinejection" Mitigation

In 2026, AI coding tools interact directly with issues, external APIs, and untrusted user inputs. Attackers may attempt to inject malicious instructions (e.g. instructing the agent to exfiltrate files or execute shell commands).

### Defensive Rules
- **Sanitize External Data**: Untrusted text from Issues or PR comments must never be passed to agent system contexts without data-marking (`<untrusted_content>`).
- **Never Auto-Execute Shell Scripts**: Sensitive execution steps must always involve human oversight.
- **Review Agent Verification**: Pull requests generated by AI agents must undergo human and automated static analysis before merging.

## 3. AI Agent Permission Tiers

Prose rules shape what an agent attempts; only tool configuration, OS sandboxing, hooks, and server-side controls restrict what it can do. Every agent action is therefore classified in [`.agents/rules/permission-rules-general.md`](../../.agents/rules/permission-rules-general.md):

- **A — Always allow**: read-only work and edits to ordinary files inside the version-controlled workspace.
- **C — Conditionally allow**: running project code inside a sandbox, network access to allowlisted registries and documentation, scope-limited actions, and per-action human approval for pushes, dependency changes, destructive local operations, and edits to AI or CI configuration.
- **N — Never allow**: secret access, privilege escalation, disabling guardrails, irreversible destruction, executing downloaded code, production changes, self-approval, exfiltration channels, publishing, and container escape.

Tool-specific configurations, the research behind each rule, and verification steps are described in the [AI permission guide](ai-permission-guide.md).
